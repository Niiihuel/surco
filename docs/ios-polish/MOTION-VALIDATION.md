## Implemented behavior and boundaries

- **Stable chrome and scroll continuity.** Content scrolls beneath the header, miniplayer and tab bar with edge fades and enough top/bottom space to reach the first and final rows. Persistent controls keep their identity while page content enters with a route-specific key. Passive header/navigation surfaces block taps from reaching covered rows without introducing an extra focus target. Source `4c76716` makes the compact player's title/transport background opaque enough to keep underlying text from showing through. A later simulator finding exposed empty-Home text behind the tab bar; `ef6dbbb` adds an opaque `SCHEME.canvas` background to that bar, with four focused Linux recaptures verifying that fix; the final simulator capture and launch smoke check are also approved. See [mobile shell](../../crates/app/src/view/mobile.rs) and [scroll insets/fades](../../crates/app/src/view/mobile/chrome.rs).
- **Compact headers.** Album, artist and playlist titles condense after their actual title anchor passes the 76-point header boundary; their compact Play dispatches the existing page action. The scrolled player header shows current title/artist, Like, Play/Pause and a progress strip. Separate stable IDs dispatch the same commands as the full controls. Queue navigation stays internal and does not replay the player's entrance.
- **Player content.** Cover, title/artist, elapsed/remaining time, seek, transport, connections, sharing, queue and more actions use current playback state. Lyrics preview reads only the current track's lines; the artist card appears only when matching catalog data exists. Loading/missing/error states remain explicit. Artist biography/statistics and credits are never invented. Library import actions have full 44-point touch targets, verified by the `4c76716` recapture. See [player content](../../crates/app/src/view/mobile/player.rs).
- **Interactive player motion.** Opening takes 320 ms, return after a cancelled/short pull 220 ms, and closing 240 ms. A downward pull can start on the header, or in the player body only when its scroll offset was at the top at touch start. Primary-touch identity, an 8-point direction/slop decision, cancellation and 120-point distance or 900-point/s recent-velocity completion preserve taps, sliders, text controls and horizontal pans. Once claimed, the gesture cancels the tree's press and consumes the corresponding pan/release. An interrupted entrance freezes at touch down so the grabbed point remains under the finger. Dismissal returns to history, or Home when history is empty, without pausing audio. See [Host motion](../../crates/app/src/mobile_motion.rs).
- **Visual underlay.** The Host stores the last non-player page's paint commands for the background while the player moves. That frame has no hit regions or accessibility nodes, and is used only at the same viewport size. limn translates the current surface's paint, pointer regions, accessibility and scroll geometry together; Surco does not manually rewrite draw commands.
- **Search and indicators.** The Search title header retargets between 76 and 0 points as editing changes; keyboard geometry remains handled by the native bridge. Vertical lists and horizontal shelves opt into scroll indicators with a 650 ms activity hold and 220 ms fade. Hidden indicators leave no invisible scrollbar hit target; the viewport remains scrollable.
- **Reduce Motion.** Either Surco's setting or the public UIKit system preference disables autonomous motion in the tree, keyboard-inset transition and player/Search transitions. Direct player manipulation still follows the finger. The native observer wakes the Rust UI when the system preference changes; this path has source/binding tests, with the physical iOS switch check still pending. Static edge shading remains for legibility. See [Host integration](../../crates/app/src/lib.rs), [Rust native UI binding](../../crates/app/src/ios_ui.rs) and [UIKit bridge](../../ios/SurcoView.m).
- **Launch.** An OS-owned static dark [launch storyboard](../../ios/LaunchScreen.storyboard) uses the existing Surco mark, centered with fixed size. Its opaque background matches the first Rust canvas, including outside the safe area. It adds no timer, network gate or second animated splash. Storyboard/catalog metadata and asset/background consistency are covered by packaging-script tests.
- **Lyrics lifecycle fix.** Changing current track clears the remembered active line and requests a viewport reset, including before the first timed line and A→B→A. Ordinary same-track ticks preserve manual scrolling and active-line following still works. Opening the mobile player fetches its own lyrics/artist data without relying on desktop panel visibility. The Host applies the reset before layout; preview uses current-track lines rather than stale results. See [playback state](../../crates/app/src/state.rs) and [Host regression tests](../../crates/app/src/lib.rs).
